# Skills 使用指南

> 本文件供 Claude Code 在开发本工程时参考。共 18 个 skill，按使用场景分为 5 类。

---

## 一、需求与设计阶段

### `to-prd` — 从对话上下文生成 PRD
- **触发：** "写个 PRD"、"整理需求文档"
- **流程：** 探索代码库 → 识别测试缝 → 按模板写 PRD → 发布到 Issue Tracker（标签 `ready-for-agent`）
- **注意：** 不采访用户，直接从上下文综合。依赖 `setup-matt-pocock-skills` 已配置。

### `grill-with-docs` — 用领域术语拷问设计
- **触发：** "审查一下这个方案"、"帮我校准术语"
- **流程：** 逐题采访用户 → 用 CONTEXT.md 挑战模糊术语 → 即时更新术语表 → 必要时提议 ADR
- **注意：** 会产生副作用（更新 CONTEXT.md、创建 ADR）。能用代码库回答的问题不要问用户。

### `grill-me` — 单方面拷问用户的设计
- **触发：** "grill me"、"拷问我"
- **流程：** 沿决策树逐分支深入，每题附带推荐答案，一次只问一个问题
- **与 grill-with-docs 的区别：** 不更新文档，纯粹对话式拷问

### `prototype` — 建造抛弃式原型
- **触发：** "做个原型"、"试一下这个交互"
- **流程：** 选分支（逻辑→终端 App / UI→多风格页面）→ 构建 → 获取答案 → 删除原型
- **铁律：** 抛弃式，不写测试，不留仓库。答案比代码重要。

### `zoom-out` — 上升一层抽象看代码
- **触发：** "给我一个概览"、"这部分代码干什么的"
- **行为：** 单次指令，输出相关模块和调用者地图（使用领域术语）
- **注意：** 用户手动调用，模型不会自动触发（`disable-model-invocation: true`）

## 二、任务拆分与跟踪

### `to-issues` — 把计划拆成独立 Issue
- **触发：** "创建 Issue"、"拆分任务"
- **流程：** 收集上下文 → 探索代码库 → 按垂直线切分（穿越全部层）→ 用户确认粒度 → 按序发布
- **核心概念：** HITL（需人工）/ AFK（可无人值守），优先 AFK。每条 slice 必须可独立演示。

### `triage` — Issue 分诊状态机
- **触发：** "分诊 Issue"、"整理 Issue"
- **流程：** 拉取未分诊列表 → 按桶展示 → 对单个 Issue 推荐分类 → 执行标签操作
- **状态流转：** `needs-triage` → `needs-info` / `ready-for-agent` / `ready-for-human` / `wontfix`
- **注意：** Bug 类必须先尝试复现。每次发言以 `> *This was generated by AI during triage.*` 开头。

## 三、开发与实现

### `tdd` — 测试驱动开发
- **触发：** "用 TDD 开发"、"先写测试"
- **流程：** 规划接口 → 写第一条集成测试（RED）→ 最小代码通过（GREEN）→ 逐行为递增 → 重构
- **铁律：** 垂直线（tracer bullet），禁止水平切片。每次只加一个测试。RED 时不重构。

### `diagnose` — 系统性调试
- **触发：** "调试这个 bug"、"排查一下"
- **流程：** 构建反馈回路（pass/fail 信号）→ 复现 → 生成 3-5 个可证伪假设 → 插桩 → 修复+回归测试 → 清理
- **铁律：** 没有反馈回路之前不进复现阶段。调试标记用 `[DEBUG-xxxx]` 前缀，事后全删。

### `improve-codebase-architecture` — 架构深化
- **触发：** "优化架构"、"找重构机会"
- **流程：** 探索摩擦点（浅模块、高耦合、难测试）→ 生成 HTML 报告（Tailwind+Mermaid，写入临时目录）→ 用户选候选 → 深入设计接口
- **术语体系：** module / interface / implementation / depth / seam / adapter / leverage / locality（参见 LANGUAGE.md）

### `caveman` — 极简通信模式
- **触发：** "caveman mode"、"少说点"、"简短点"
- **行为：** 删冠词/填充词/客套话，保留术语和代码，用箭头表达因果，允许碎片句
- **注意：** 持久生效，直到用户说 "stop caveman"。安全警告时自动暂停。

## 四、基础设施搭建

### `setup-matt-pocock-skills` — 一次性技能基础设施
- **触发：** 首次使用 to-issues/to-prd/triage/diagnose/tdd 等之前
- **流程：** 探索仓库 → 逐项确认（Issue 追踪器位置、标签词汇表、领域文档布局）→ 写入 `## Agent skills` 到 CLAUDE.md + 创建 `docs/agents/*.md`
- **注意：** 不自动触发（`disable-model-invocation: true`），必须显式调用。

### `git-guardrails-claude-code` — Git 危险命令拦截
- **触发：** "加 git 安全钩子"、"防止误操作 git"
- **流程：** 确认作用域 → 复制拦截脚本 → 添加 PreToolUse Hook → 验证
- **拦截：** `push`、`reset --hard`、`clean -fd`、`branch -D`、`checkout .`/`restore .`

### `setup-pre-commit` — 配置 Husky 提交钩子
- **触发：** "配置 pre-commit"、"加提交前检查"
- **流程：** 检测包管理器 → 安装 husky+lint-staged+prettier → 创建 `.husky/pre-commit` → 创建 `.lintstagedrc` → 验证 → 提交
- **注意：** TypeScript/JavaScript 项目专用。

## 五、效率与交接

### `handoff` — 会话交接文档
- **触发：** "交接给下一个 agent"、"打包当前上下文"
- **流程：** 写摘要文档 → 保存到 OS 临时目录 → 不重复已有制品内容 → 脱敏 → 附推荐 skill 列表
- **注意：** 输出到系统临时目录，不在工作区内。

### `write-a-skill` — 编写新 Skill
- **触发：** "写一个 skill"、"创建一个新技能"
- **流程：** 收集需求（领域/用例/需脚本否）→ 起草 SKILL.md（<100 行）→ 必要时拆 REFERENCE.md/EXAMPLES.md/scripts/ → 用户审阅
- **核心要求：** 描述字段必须有触发短语（"Use when..."），第三⼈称，≤1024 字符。

### `migrate-to-shoehorn` — TypeScript 类型安全迁移
- **触发：** "用 shoehorn 替换 as 断言"
- **行为：** 在测试文件中将 `as Type` → `fromPartial()`，`as unknown as Type` → `fromAny()`
- **铁律：** 仅测试代码，生产代码禁用。

### `scaffold-exercises` — 创建练习目录
- **触发：** "搭练习框架"、"创建课程章节"
- **行为：** 按命名规范创建目录 → 写 stub readme → 运行 linter → 修复至通过
- **适用：** 教育/课程类项目。
